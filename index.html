Where Atlas is right now

The path so far, in five steps.

  1. 1

    We published the question first

    Done

    Before writing client code, Atlas Papers 001 and 002 asked publicly whether the Internet was missing a person-controlled identity layer — and invited networking and security experts to say we were wrong.

    Read the papers →
  2. 2

    We built a real identity engine

    Built

    A credential rooted in a phrase only the person holds, a published verification key, and a different, unlinkable identifier for every service Atlas connects to — running code, not a mockup.

    See what's built →
  3. 3

    We proved it end to end

    Verified

    A demonstration relying party verifies an Atlas identity from the published key alone, and the exit a device connects through keeps no record of which account used it — both confirmed live, not only in design documents.

    Read the trust paper →
  4. 4

    Real people are testing it

    Happening now

    Mac, iPhone, and Android apps carry this identity today, in closed TestFlight and download-portal testing — the same system described above, not a separate demo build.

  5. 5

    What has to happen before anyone can sign up

    Not yet

    One step remains: an outside-reviewed cryptographic change (blind signatures) that turns today's no-storage rule into a mathematical guarantee. Testing stays closed and curated until it ships.

The question

Is the Internet missing a foundational layer?

Authentication, VPNs, Zero Trust, identity providers, certificates, device posture, and access control have improved. Yet a person's digital presence remains fragmented across accounts, applications, networks, and institutions.

Atlas does not begin by proposing another replacement product. It asks whether existing technologies can be organized around a persistent, portable, person-centred Internet presence.
